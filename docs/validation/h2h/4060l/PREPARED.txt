The expert store was built on the RTX 4090 by the same commit; the checkpoint copy left out the expert weights, which training never reads once the store exists.

How the laptop's files were prepared. Everything sat in one folder, ~/poros-run, on the laptop's internal drive. The expert store (the model's experts quantized to NF4, 15.0 GB, one .sss file and its index) was built by the same Poros commit on the RTX 4090 box from Qwen/Qwen3-30B-A3B at revision ad44e777bcd18fa416d9da3bd8f70d33ebb85d39 and copied to the laptop unchanged. The checkpoint folder on the laptop holds every file of that revision under its own name and size; in each weight file the safetensors header and the non-expert tensors (attention, norms, routers, embeddings: 435 tensors, 3.08 GB) are present at their offsets, fetched by HTTP range requests, and the expert tensors' byte ranges (57.98 GB) are holes that were never downloaded. A first run that builds the store needs the whole 61 GB checkpoint; a run that reuses a store reads only each weight file's name and size and the non-expert tensors (poros/moe/load.py: an expert tensor is 'reused from the .sss file: never read'). Before the freeze, on the RTX 4090 at commit a2531867, a run with every expert tensor of the full checkpoint made unreadable trained to its reference adapter digest; that record (t2_noexpert) is from before the freeze and is not part of this set. At the frozen commit the laptop's runs trained on these files: their records name the store, its sha256 equal to the copy built on the RTX 4090. Unsloth was not run on the laptop. The token length of the rows is recorded in every run.
